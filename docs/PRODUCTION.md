# Production operations

## Security prerequisites

Set `KCEV_AUTH_REQUIRED=true` and generate independent `KCEV_OPERATOR_TOKEN`, `KCEV_SESSION_SECRET`, and `KCEV_EXECUTION_CONTEXT_SECRET` values with at least 32 cryptographically random bytes each. Configure `KCEV_SECRETS_ENCRYPTION_KEYS` as a secret-manager-injected JSON object whose values are exactly 32 random bytes encoded as 43-character base64url, then select one public key ID with `KCEV_SECRETS_ACTIVE_KEY_ID`. Store key material in a managed secret service and encrypted disaster-recovery escrow, never source control. The keyring protects tenant integration secrets with AES-256-GCM, tenant and key-ID authenticated data, and key-identified envelopes. Loss of every key that protects a stored record intentionally makes that credential unrecoverable. `KCEV_SECRETS_ENCRYPTION_KEY` is accepted as the legacy v1 decryption key during migration; a deployment with no explicit keyring writes `v2.legacy` for compatibility but should be upgraded before production rotation. Remove the bootstrap operator token after named administrators or SSO are proven. The execution-context secret signs the project, commit, actor, request correlation, provider, autonomy limits, and policy snapshot persisted with every admitted run. Rotating it intentionally invalidates resume for previously signed runs. Set `ORIGIN` to the public HTTPS origin and list any additional HTTPS origins in `KCEV_TRUSTED_ORIGINS`. Terminate TLS at a trusted ingress and restrict `/api/metrics` to the monitoring network or authenticated scraper.

Rotate tenant integration encryption keys in two phases. First add the new key to `KCEV_SECRETS_ENCRYPTION_KEYS`, retain every key currently in use plus the legacy v1 key when applicable, set the new active ID, deploy, verify a backup, and run `npm run secrets:rotate -- --dry-run`. Then run `npm run secrets:rotate -- --execute`. Re-encryption traverses stable tenant-ID cursors in bounded batches, uses the inspected row revision as an optimistic lock, changes the OIDC revision to invalidate in-flight login state, and writes a `reencrypted` event containing old/new key IDs but no secret. Repeat the dry run until `pending` and `failed` are zero; confirm `/api/diagnostics` reports `retirementReady: true`; update recovery escrow; only then remove retired keys and redeploy. The command continues past individual failures, reports only a one-way tenant reference, and exits nonzero when any record fails. Diagnostics obtains counts through an aggregate service RPC and does not download tenant rows or encrypted payloads.

Provider credentials remain server-only. Set the provider keys you intend to use: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `GEMINI_API_KEY` or `GOOGLE_API_KEY`, `XAI_API_KEY`, and optionally pin `KCEV_OPENAI_MODEL`, `KCEV_ANTHROPIC_MODEL`, `KCEV_GEMINI_MODEL`, `KCEV_XAI_MODEL`, or `KCEV_OLLAMA_MODEL`. Never expose these variables to browser bundles.

Configure current input and output prices per million tokens with `KCEV_<PROVIDER>_INPUT_USD_PER_MILLION` and `KCEV_<PROVIDER>_OUTPUT_USD_PER_MILLION`, where provider is `OPENAI`, `ANTHROPIC`, `GEMINI`, or `XAI`. Pricing changes independently of application releases, so verify it against the provider contract when deploying or changing models. Rates never fall back across providers. When a positive cost ceiling is enabled but the selected cloud provider has no valid rates, admission fails closed before planning begins. Local providers always report zero API spend.

Readiness evidence is scoped to the exact provider/model pair. Probing one Ollama model does not authorize another installed model, and changing a model in the task runner refreshes governance for that pair. Run the visible capability probe after selecting a new model; admission remains blocked until that model returns a valid live structured response. Cloud model choices come from server configuration, while Ollama choices come from the live local inventory.

## Deployment

```sh
npm ci
npm run ai:sync
npm run ai:check
npm run ai:test
npm run build
HOST=0.0.0.0 PORT=3000 npm start
```

The production entrypoint rejects new traffic immediately on SIGTERM/SIGINT, waits `KCEV_DRAIN_DELAY_MS` for endpoint removal, closes connections, and enforces `KCEV_SHUTDOWN_GRACE_MS`. Run it under a supervised service account with access only to explicitly mounted workspaces. Put a TLS reverse proxy or private ingress in front of it, and keep the process manager responsible for restart policy, log collection, and environment injection.

Each replica admits at most `KCEV_MAX_INFLIGHT_REQUESTS` concurrent requests (default `200`). Excess traffic receives a cache-disabled HTTP 503 with `Retry-After` and `X-Concurrency-*` capacity headers; `/api/health/live` remains exempt so liveness stays meaningful during saturation. Tune this limit from measured workload evidence, container memory, and downstream connection budgets. Run `npm run capacity:test -- --url <deployed-endpoint> --requests 1000 --concurrency 50 --p95-ms 750 --max-error-rate 0.01` before increasing it.

Build immutable application and migration images from `Dockerfile` and `Dockerfile.migrate`. Replace the zeroed image digests in `deploy/kubernetes/*.yaml`, create `kcevagent-secrets`, run the migration Job to completion, and only then roll out `base.yaml`. The baseline uses two replicas, zero-unavailable rolling updates, startup/liveness/readiness probes, non-root read-only containers, dropped capabilities, a disruption budget, stabilized autoscaling, bounded resources, and restricted network egress. Adapt the workspace PVC, ingress, egress destinations, and secret integration to the target cluster.

## Health and telemetry

- `GET /api/health/live`: process liveness; never depends on external services.
- `GET /api/health/ready`: writable storage, durable run-lease schema, execution-context signing, and required-provider readiness.
- `GET /api/metrics`: Prometheus exposition, authenticated in production.
- `POST /api/automation/maintenance`: idempotent maintenance runner for scheduler-triggered diagnostics and stale provider readiness probes.
- `GET /api/diagnostics`: redacted readiness bundle for storage, memory, auth posture, integration-secret rotation readiness, provider probes, local model inventory, and event-log replayability.
- `GET /api/governance?provider=<provider-id>&mode=interactive`: redacted run-readiness policy report. Returns `allow`, `allow_with_warnings`, or `block` with exact operator actions before a run is started.
- `GET /api/operations/slo?limit=50`: persisted-run SLO and incident report. Computes success rate, needs-attention rate, provider readiness ratio, p95 duration, spend, token totals, recent runs, and operator actions from the run ledger and provider diagnostics.
- `GET /operations`: role-aware production control plane for SLOs, incidents, dependency health, lease/approval workload, process telemetry, and remediation.
- `GET /api/runs/:id/events`: persisted run event timeline for replay, audit, and incident review.
- `GET /api/runs/:id/export`: portable run audit bundle with signed execution context, run, ledger, events, task graph, diagnostics, component hashes, and a bundle SHA-256 digest.
- stdout/stderr: newline-delimited structured JSON logs with request IDs and redacted sensitive fields.

Alert on readiness failures, HTTP 5xx rate, provider 429/5xx rate, verifier rejection rate, run latency, exhausted retries, missing event timelines for completed runs, and storage growth. Preserve logs and event ledgers according to organizational retention policy.

Agent execution exports `kcev_request_admission_active`, `kcev_request_admission_limit`, `kcev_request_admission_rejections_total`, `kcev_agent_runs_total`, `kcev_agent_steps_total`, `kcev_agent_tokens_total`, `kcev_agent_run_duration_ms`, `kcev_agent_estimated_cost_usd`, `kcev_agent_run_lease_claims_total`, `kcev_agent_run_lease_contention_total`, `kcev_agent_run_lease_lost_total`, and `kcev_agent_run_lease_releases_total`. Labels are deliberately limited to provider, status, operation, token direction, and bounded lease outcomes; tasks, prompts, run IDs, models, paths, raw outputs, and tenant identifiers are excluded from metric labels. Structured lease logs include run and owner correlation for incident response but never include the opaque lease token.

Propagate the W3C `traceparent` header through the ingress. KcevAgent preserves the upstream trace ID, creates a server span, returns `traceparent` and `x-request-id`, and attaches both to structured logs. Scrape `/api/metrics` from every replica because counters and histograms are process-local; use `/operations` and Supabase-backed SLO reports for tenant-wide evidence.

Apply `deploy/kubernetes/monitoring.yaml` when the Prometheus Operator CRDs are installed. Create a `kcevagent-monitoring` secret whose `token` key contains a dedicated viewer access token; the ServiceMonitor uses it as a bearer credential and never embeds credentials in source. The accompanying PrometheusRule covers replica loss, HTTP error rate, audit persistence, shared admission, and lease contention. Replace every `example.invalid` runbook URL with the deployed incident handbook URL before enabling paging.

Use `/api/operations/slo` as the human-readable incident source for on-call review. The endpoint returns HTTP 503 when critical SLOs are breached and HTTP 200 for healthy or warning-only windows. Default thresholds require at least 90% verified completed runs, no more than 10% needs-attention runs, at least 20% provider readiness, and proven event replay. Tune external alert thresholds only after enough production run volume exists to avoid noisy early windows.

Use audit bundles for external review and incident handoff. The bundle is JSON, cache-disabled, and includes the admitted correlation ID, policy fingerprint, signed execution context, and deterministic component hashes so a recipient can verify the run, ledger, event timeline, graph, and diagnostics were not altered after export.

Schedule maintenance externally, for example every 15-60 minutes, by calling `POST /api/automation/maintenance` with the operator bearer token. The runner is idempotent: it refreshes diagnostics, probes stale providers, records metrics, logs a redacted completion event, and returns next actions without mutating runs or source files.

Use the governance report as the admission gate for production runs. Hard failures in storage, memory, or security block execution. A selected provider that has not passed readiness probes also blocks execution. Unknown provider ids are blocked instead of falling back to another provider. Event-log or local-model gaps are warnings unless they become failed checks, allowing supervised runs while still surfacing audit and fallback risk. The dashboard disables new run submission when the active governance report is blocked, and `POST /api/runs/stream` enforces the same policy before opening the NDJSON stream.

## Authentication

KcevAgent uses individual access tokens for named identities and exchanges them for signed, eight-hour HttpOnly sessions. Raw access tokens are not stored in browser cookies. Roles are enforced server-side: `viewer` can read project and evidence data, `operator` can also plan and execute runs, and `admin` can additionally register projects and administer policy.

Generate a named identity without placing its plaintext token in configuration:

```powershell
npm run auth:operator -- --id=alice@example.com --name="Alice" --role=admin
```

Give the displayed token to that person once and add the emitted object to the `KCEV_OPERATORS_JSON` array. Add `--tenant-id=<uuid> --tenant-name="Organization"` when generating a static identity for a non-bootstrap organization. Durable identities issued in Administration automatically inherit the signed-in administrator's organization. Users enter only their personal token; its digest selects the organization server-side, and no tenant ID is requested in the login UI. Set `KCEV_SESSION_SECRET` and `KCEV_EXECUTION_CONTEXT_SECRET` to separate random values of at least 32 characters. `KCEV_OPERATOR_TOKEN` is a bootstrap administrator credential for initial setup and should be removed after named administrators are verified. API clients send a personal token as `Authorization: Bearer <token>`; browser clients exchange one at `POST /api/auth/session`. Removing an identity or changing its role invalidates its existing sessions on the next request; rotating `KCEV_SESSION_SECRET` invalidates every session. State-changing requests also enforce same-origin or configured trusted-origin checks.

Organization lifecycle management is a separate platform authority, not a tenant `admin` permission. Add trusted named identity IDs to `KCEV_PLATFORM_ADMIN_IDS`; removing an ID invalidates its elevated sessions on the next request. While configured, the bootstrap administrator also has platform authority for recovery. A platform administrator uses **Administration > Organization provisioning** to atomically create the tenant and first administrator. Only the SHA-256 credential digest reaches Postgres; the plaintext token is returned once with `Cache-Control: no-store`. Suspending an organization atomically records the lifecycle event and immediately rejects its durable tokens, configured tokens, existing sessions, and company SSO identities. The API prohibits changing the status of the organization that owns the current session; use a platform administrator from another active organization. Ordinary tenant administrators receive HTTP 403 from `/api/platform/*` even if they call it directly.

Durable identities have one home organization and may receive audited memberships in other organizations. The account owner copies the non-secret `organization-id:identity-id` reference from **Administration > Organization memberships** and provides it through an approved business channel. An administrator in the destination organization grants an organization-specific role. The top-bar selector appears when more than one membership is active; switching issues a new v3 session only after exact home-account, identity, target-tenant, membership, and tenant-status resolution. Removing an external membership affects only that organization. Revoke the home identity under **Identity and access** to terminate the credential and every membership globally. Home roles are changed only in the identity directory, preventing divergence between initial login and session revalidation. Bootstrap and static configured operators are intentionally single-organization accounts and do not receive an account reference.

For company SSO, an organization administrator opens **Administration > Company SSO**, copies the exact callback URL into the identity provider, and enters the issuer, client ID, client secret, scopes, and any additional trusted endpoint origins. KcevAgent validates live discovery before saving. The plaintext secret exists only in the request and process memory, is encrypted with AES-256-GCM using tenant and key-ID authenticated data, and is never returned by the API. Credential rotation creates a new connection revision and invalidates every in-flight authorization transaction; platform key re-encryption does the same. Configuration, lifecycle, and re-encryption events are service-role-only and audited without secret material.

`KCEV_OIDC_ISSUER`, `KCEV_OIDC_CLIENT_ID`, and `KCEV_OIDC_CLIENT_SECRET` remain an optional deployment-managed fallback for the bootstrap organization only. Other organizations never inherit them. Provision each user in the intended organization's **Identity and access** section with an ID equal to the lowercase verified email claim before sign-in. Users enter that organization's human-readable slug before leaving for the identity provider. The server resolves the active tenant and its OIDC revision, then seals the tenant UUID, name, slug, and provider fingerprint into the signed ten-minute PKCE transaction. Callback processing rechecks organization and connection status, rejects revision substitution and cross-tenant membership, and writes the federated-login event to that same tenant. The authorization-code flow also uses signed state, nonce, PKCE `S256`, server-side code exchange, asymmetric ID-token signatures, exact issuer/audience checks, and issuer JWKS. Federation never assigns roles from untrusted token claims; the durable KcevAgent directory remains authoritative.

## Backup and recovery

Use Supabase point-in-time recovery and scheduled logical exports for database recovery. Back up the shared workspace volume and `.kcevagent/artifacts` according to project retention policy. Restore into an isolated tenant, run checksum validation and `/api/health/ready`, compare project/run/event/artifact counts, replay a sample audit bundle, and only then admit traffic.

For Supabase-backed storage, apply migrations from `supabase/migrations` in filename order, create the bootstrap tenant row, and set `SUPABASE_TENANT_ID` to that UUID. Set `KCEV_TENANT_DISPLAY_NAME` to the customer-facing organization name. Migrations `202607130001_run_leases.sql` through `202607130011_organization_memberships.sql` are mandatory before this build receives traffic; readiness fails when leases, approvals, the identity directory, request-bound tenant uniqueness, controlled organization lifecycle, tenant-owned SSO storage, managed secret rotation, organization memberships, audit-chain verification, or shared rate limiting are unavailable. Production request admission fails closed when the shared limiter cannot be reached, preventing a replica-local bypass. Use only a server-side secret key, rotate any key that appears in chat or logs, and rely on Supabase point-in-time recovery according to your plan.

Every task begins with `POST /api/runs/preflight`. The response contains the persisted plan and a one-time approval token; store that token only in transient client state. `POST /api/runs/stream` requires the preflight run ID and token, atomically consumes the pending approval, claims the run lease, and executes the reviewed plan without replanning. Approval tokens expire after 30 minutes and cannot be replayed. `DELETE /api/runs/:id/approval` records an explicit rejection for discarded plans.

`SUPABASE_TENANT_ID` identifies the bootstrap organization and pre-authentication control scope. Durable personal tokens resolve server-side to exactly one tenant, and signed sessions preserve that tenant binding for the entire request. Every run, event, memory, approval, lease, identity, and audit operation uses the authenticated request context. Never accept a tenant UUID from a browser request, proxy header, query parameter, or form field. Additional tenants and their first administrator are created in one service-role-only database transaction; organization slugs and credential digests are globally unique, and the lifecycle event stores the actor but no plaintext secret.

Stopped and needs-attention runs resume from the first non-verified step. Resume first atomically claims the durable run lease; an active owner returns HTTP 409, while an expired lease can be reclaimed with an incremented attempt. Model-backed runs reconstruct the persisted provider and model adapter, then send resumed tool evidence through the same independent model verifier used by a new run. Resume never silently substitutes deterministic execution for OpenAI, Claude, Gemini, Grok, or Ollama. If the persisted provider is no longer configured or reachable, resume fails visibly and leaves the existing ledger intact.

## Rollback

Deploy the prior immutable application digest while keeping the authoritative Supabase tenant and shared workspace attached. Database migrations are forward-only: restore into an isolated tenant before any destructive schema reversal. Set the configured provider back to a known-good provider if one execution path is impaired, export affected ledgers, validate bundle checksums, and verify readiness before restoring full traffic.

Apply `deploy/kubernetes/recovery.yaml` after replacing image digests and provisioning the `kcevagent-recovery` encryption secret. The daily encrypted portable backup targets a 24-hour RPO and the monthly isolated restore drill continuously tests recoverability. Follow `docs/DISASTER_RECOVERY.md`; the backup PVC must be replicated or snapshotted off-site because a same-cluster volume is not a disaster-recovery boundary.
